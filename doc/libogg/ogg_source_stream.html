ogg_source_stream

declared in "ogg/source.h";

The ogg_source_stream is an opaque decode stream that behaves like an ogg_stream_state, but additionally tracks which byte ranges of the original input each decoded packet was assembled from. It is intended for callers that take pages from the sync layer and later need to map a decoded packet back to the positions in a recording it came from, without keeping the whole recording in memory.

The relevant functions are:

ogg_source_stream *ogg_source_stream_new(int serialno);
Creates a source-tracking decode stream for the given serial number. Returns NULL on allocation failure.
void ogg_source_stream_free(ogg_source_stream *ss);
Destroys the stream and releases all decode and tracking state.
int ogg_source_stream_reset(ogg_source_stream *ss, int serialno);
Resets the stream to its initial state, selects a new serial number and releases all buffered packet and tracking state.
int ogg_source_stream_pagein(ogg_source_stream *ss, ogg_page *og, ogg_int64_t offset);
Submits a page, exactly like ogg_stream_pagein(). offset is the absolute byte position of the page's capture pattern within the original input. A negative offset, or a page whose header+body extent would overflow a signed 64 bit offset, is rejected with a return value of -1 before any stream state is modified. Pages with a non-matching serial number or a nonzero version are rejected as in ogg_stream_pagein() and contribute no source information.
int ogg_source_stream_packetout(ogg_source_stream *ss, ogg_packet *op, ogg_source_info *info);
int ogg_source_stream_packetpeek(ogg_source_stream *ss, ogg_packet *op, ogg_source_info *info);
Like ogg_stream_packetout() and ogg_stream_packetpeek(); either op or info may be NULL, and the consumption rules of the original functions apply unchanged (in particular, packetpeek does not consume a complete packet, but does consume a hole marker). When a packet is returned and info is non-NULL, info describes the input ranges the packet payload was assembled from. When the return value is 0 (need more data) or -1 (hole in the stream), info is cleared to "no source" so stale ranges from an earlier packet are never mistaken as current.

Source spans

typedef struct {
  ogg_int64_t offset;
  long bytes;
} ogg_source_span;

typedef struct {
  const ogg_source_span *spans;
  size_t count;
} ogg_source_info;

Each span covers a contiguous range of packet payload bytes in the original input; offset uses the same coordinate space as the offsets passed to ogg_source_stream_pagein(). Only payload bytes are covered: page headers, lacing tables and the payload of dropped partial packets never appear. Spans adjacent within a single page are merged; spans are never merged across page boundaries, so a packet that spans pages (possibly with pages of other streams interleaved) reports one span per contributing page fragment. Concatenating the spans in array order reproduces the returned packet byte for byte. A zero-length packet reports a count of 0.

The spans array is owned by the stream and remains valid only until the next call to any ogg_source_stream_* function on the same stream. Callers must copy the data if they need it longer, and must not free it.

Holes

Missing pages, page sequence jumps and continuation pages without a pending partial packet are handled exactly as by the plain decode stream: the partial data is dropped, a hole is reported (return value -1, consuming the hole marker), and packets completed afterwards carry only the source ranges of the pages that actually contributed to them -- never the ranges of dropped data.
