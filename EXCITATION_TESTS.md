# Excitation reconstruction contract tests

These tests pin down the numerical behaviour of the narrowband excitation
that `nb_decode()` builds **before** LPC synthesis, in the floating-point
build (`-DFLOATING_POINT`) only. They are a safety net for the upcoming
platform-specific optimization work: an optimization that changes any of the
documented relations below will fail here before it can change decoded audio.

Scope and non-goals:

* Only the current floating-point build is covered.
* Only normal encoded frames in narrowband modes 3, 5 and 7 are used.
* Packet loss (`nb_decode_lost`), comfort noise / DTX and the fixed-point
  branch are intentionally not extended by this work.
* No speech files and no external tools are involved. All waveforms are
  generated by deterministic C expressions and all packets are produced by a
  normal production encoder run inside the test.
* No production source, codebook or fixed harness (`task_support/`,
  `devcheck/`) is modified. The production decoder functions are only the
  system under test; they are never used to compute an expected value.

## Files

| File | Role |
| --- | --- |
| `tests/excitation_contract.c` | The contract. Exports `task_cases`/`task_case_count`, defines no `main()`, includes `task_support/check.h`. |
| `tests/check_excitation_mutations.sh` | Builds two mutated, still-compilable copies of the library and proves the contract catches them. |
| `task_support/driver.c` | Existing harness that runs the registered groups and returns non-zero on failure. |

The registered groups are `adaptive`, `innovation` and `frames`, each with at
least one real test function. Every comparison goes through `TASK_CHECK`;
a successful test function returns `0`.

## Bit-stream conventions

Speex packs bits MSB first inside each byte. The contract implements its own
cursor (`BitReader`/`BitWriter`) over a raw byte buffer and never calls
`speex_bits_unpack_unsigned` to interpret a field under test. Frame layout
for the three modes is:

1. wideband flag, 1 bit (always `0` for narrowband packets);
2. submode id, 4 bits (`3`, `5` or `7`);
3. LSP indices, 6 bits each — three fields (18 bits) in mode 3, five fields
   (30 bits) in modes 5 and 7;
4. global excitation gain index `qe`, 5 bits;
5. four subframes, each:
   * pitch index then gain index (adaptive codebook);
   * optional per-subframe gain correction (1 bit in mode 3, 3 bits in
     modes 5 and 7);
   * one split shape codebook, and a second one only in mode 7.

Per-frame payloads observed from legal encodings are 160 bits (mode 3, byte
aligned, no terminator), 300 bits (mode 5) and 492 bits (mode 7). When the
payload is not byte aligned the remaining bits are the Speex terminator: a
leading `0` followed by one-bits, which the contract checks explicitly.

Failures are reported in separate channels so the first deviation can be
attributed to one cause:

* `BIT_CURSOR_MISMATCH` — bit position, consumed width or terminator;
* `PITCH_DOMAIN_MISMATCH` — pitch outside `[17, 144]`;
* `INDEX_DOMAIN_MISMATCH` — gain/shape index outside its codebook;
* `CONTENT_MISMATCH` — a numerical sample disagreement.

Floating-point content uses the tolerance `1e-4 + 2e-5 * |reference|`.

## History coordinates

The decoder keeps one excitation buffer. At the start of every frame
`nb_decode()` shifts it by 160 samples, then sets `st->exc` to the first
sample of the new frame. Within a subframe the local coordinate `j` runs over
`0..39`; every adaptive-codebook read uses a negative (or, for short pitch,
an earlier same-frame) coordinate relative to that origin.

The contract keeps its **own** history array in global sample coordinates
(`frame * 160 + subframe * 40 + j`) with a zero pad in front of sample zero,
matching the decoder's zero-initialized buffer. The reference history is
propagated solely from the reference result of the previous subframe; it is
never refreshed from production state between comparisons. Under
`TASK_OBSERVE` the test additionally snapshots the production history window
read-only and cross-checks it against the self-propagated reference.

For tap `i` in `{0,1,2}` the delay is `pp = pitch + 1 - i` and the tap gain
is `gain[2-i]`. The contribution at local coordinate `j` is:

* first segment, `0 <= j < min(40, pp)`: read `H[j - pp]`;
* second segment, `min(40,pp) <= j < min(40, pp + pitch)`: read
  `H[j - pp - pitch]` — at most one additional period;
* afterwards the tap contributes exactly zero.

This models the two production loops directly. It is neither an infinite
periodic continuation nor a recursion into samples being computed: every
indexed sample already exists in the history. Structural tests cover:

* **short delay** (`pitch <= 40`): the second segment exists and the tail
  past `pp + pitch` is provably zero; the boundary `pitch == 40` is included
  because tap `i == 2` (`pp == 39`) still has a one-sample second segment;
* **long delay** (`pitch >= 41`): every tap fills all 40 samples from the
  first segment and the second loop never contributes;
* distinct delay/gain pairing across the three taps, including a hand-built
  three-sample case where the first sample is computed from literal history
  values, and asymmetric (non-even, non-periodic) history data.

## Codebook-to-gain scaling

### Adaptive (pitch) gains

A gain index selects a row of four `signed char` values in the read-only
codebook (`gain_cdbk_lbr`, 32 rows, for mode 3; `gain_cdbk_nb`, 128 rows,
for modes 5 and 7). The three tap gains are

```
gain[t] = 0.015625 * codebook[4*index + t] + 0.5          (t = 0,1,2)
```

i.e. `codebook/64 + 0.5`. The contract re-derives this for **every** row of
both tables and checks the tap-to-delay correspondence separately from the
raw index values. The unit test additionally packs a legal pitch/gain pair
with its own bit writer and compares the independent 40-sample reconstruction
against the production `pitch_unquant_3tap`; expected numbers still come from
the model, not from the production function.

### Innovation (shape/sign) gains and the sign bit

Each split codebook stores `signed char` shapes. In the floating-point build
one codebook element contributes

```
sign * 0.03125 * shape_cb[shape_index * subvect_size + j]
```

and contributions are **accumulated** onto the destination. The tests seed a
non-zero initial target so that an implementation mistakenly overwriting
instead of accumulating is caught.

* Narrowband codebooks (`exc_10_32_table` in mode 3, `exc_5_64_table` in
  modes 5/7) have `have_sign == 0`: there is no independent sign bit.
* The wideband high-band codebook (`hexc_table`, 5 sub-vectors of 8 samples,
  7 shape bits) has `have_sign == 1`: one sign bit precedes every shape
  index. Both forms are covered, and the independent cursor starts at a
  non-byte boundary (bit offsets 1, 3 and 5) with a sentinel bit placed
  immediately after the consumed fields; the sentinel must still read back
  in its original position.

Only the read-only tables are shared with production; the production
expander `split_cb_shape_sign_unquant` is exercised only as the system under
test.

## Subframe gain correction and double-codebook order

The 5-bit global index gives the frame-wide excitation gain
`ol_gain = exp(qe / 3.5)` in the floating-point build (where `SIG_SCALING`
is 1). Each subframe then applies its correction:

* mode 3: one bit selecting `exc_gain_quant_scal1[]`
  (`0.70469`, `1.05127`);
* modes 5 and 7: three bits selecting `exc_gain_quant_scal3[]`
  (`0.061130 .. 1.326874`);
* the correction multiplies `ol_gain` to produce `ener`.

The normalized innovation is de-normalized with `ener`. Mode 7 then runs the
**second** codebook using its own freshly decoded indices (its own bit
consumption) and combines it in this exact order:

```
innov      = ener * codebook_1
innov2     = (0.454545 * ener) * codebook_2
innov     += innov2
excitation = adaptive_contribution + innov
```

The second book therefore carries an independent weight of `0.454545` on top
of the same per-subframe energy. The final excitation is the sum of the
adaptive contribution and the combined innovation; in the floating-point
build the fixed-point `SHL32(...,1)` / `PSHR32(...,SIG_SHIFT)` pair collapses
to identity, so no extra factor of two appears.

The `frames` group runs eight frames per mode (more than the required six),
alternating two deterministic speech histories frame by frame, and compares
all 160 excitation samples of every frame against `st->exc` before synthesis,
across frame boundaries and all four subframes.

## Why the existing tests cannot prove these relations

The pre-existing checks establish different, coarser properties:

* `devcheck/baseline.c` encodes and decodes generated PCM and only asserts
  that the round trip completes and reports a remaining-bit count. It never
  inspects pitch or gain indices and has no independent expected excitation.
* The upstream `libspeex/testenc.c` smoke test likewise treats the codec as a
  black box and only requires an output file to be produced.
* A hash of final decoded audio would conflate the adaptive codebook, the
  innovation codebook, LSP quantization, gain correction and the synthesis
  filter into one number. A swapped tap gain or a mishandled sign bit could
  be masked by another stage, and such a check says nothing about bit
  consumption, short-delay termination or history coordinates.

This contract instead reads each legal index independently, interprets it
through the format codebooks, reconstructs both contributions from the
documented equations, tracks its own bit cursor and history, and reports
cursor, domain and content failures separately.

## Mutation runner

`tests/check_excitation_mutations.sh` copies the library into temporary
overlay trees (the working tree is never modified) and applies two source
mutations that must remain compilable:

1. **adaptive** — in `pitch_unquant_3tap()` the outer tap gains are
   exchanged (`gain[2-i]` -> `gain[i]` at both accumulation sites);
2. **innovation** — in `split_cb_shape_sign_unquant()` an explicit negative
   sign bit is applied as positive (`s=-1` -> `s=1`), which only affects the
   signed wideband high-band codebook path.

Each mutated binary must print `CONTENT_MISMATCH` and the task driver must
return `4`. A compile failure or a crash is explicitly rejected as a
detection. An unmutated control build must stay green.

## Running

```sh
bash task_support/run.sh baseline     # pre-existing suites first
bash task_support/run.sh target       # contract (with -DTASK_OBSERVE) + baseline
bash tests/check_excitation_mutations.sh
```

`TASK_OBSERVE` only enables additional read-only observation state in the
test; the ordinary build defines no callback and changes no ABI, and the
production sources are untouched.
