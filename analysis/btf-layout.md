# Offline split BTF layout analysis

Generated by `btf.RunRebaseLayoutAnalysis` from raw BTF blobs and a 16 byte
offline memory fragment at target address `0x4000` (pointer width 8). No kernel
module is loaded, no running kernel is accessed and no BTF file is written.

## Commands

```sh
bash task_support/run.sh baseline
bash task_support/run.sh target
```

## Byte order LE

- Structure 3 member `member` is a pointer (bit offset 0). Its stored target is 0x4000 which is inside the fragment at target address 0x4000; the pointed structure is `leaf`, so the edge is a self reference when the target address equals the fragment base.
- Integer member `value` occupies byte 8..11 (bit offset 64, 4 bytes); its interpreted value is 0x12345678 (305419896).

### What changes when the base and string section are replaced

- Base type IDs are rewritten through the caller supplied correspondence (1 -> 2). Local records keep their order and restart at ID 3 directly after the new base (3 records including void).
- Edges of retained local Type objects now reach objects of the new base; the old base graph is not referenced anymore.
- Raw name offsets stay relative to the original split string section, so local and member names are unchanged even though the replacement base carries a longer string table.

### What stays identical

- Member names, bit offsets, structure sizes, raw bytes, interpreted integer values and numeric pointer addresses are identical before and after Rebase, in both byte orders.
- The pointer cycle (local structure pointing at itself) and declaration tags attached to members are preserved; `All` still enumerates module types only.
