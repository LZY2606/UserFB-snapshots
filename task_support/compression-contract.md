Compressed ELF read contract

Primary format reference: https://gabi.xinuos.com/v42/elf/03-sheader.html , section 3.7, Compressed Sections. This is an ELF symbol/reference reading change; it does not provide a generic archive extraction API.

SHF_COMPRESSED is 0x800. ELF32 compression header: ch_type u32, ch_size u32, ch_addralign u32 (12 bytes). ELF64: ch_type u32, ch_reserved u32, ch_size u64, ch_addralign u64 (24 bytes). Every integer uses the ELF's declared endian encoding; ELF64 reserved must be zero. ch_type=1 means one complete zlib stream from immediately after this header to the section's physical end. Other types are unsupported. SHF_COMPRESSED cannot accompany SHF_ALLOC or SHT_NOBITS. ch_addralign follows normal ELF alignment rules: zero, one or a power of two. ch_size is the exact decompressed file-format byte count. A valid empty stream with ch_size=0 is accepted. Truncated headers, corrupt streams, trailing bytes, output shorter/longer than ch_size, and impossible arithmetic are rejected.

This extension operates on ELF_C_READ only (including elf_memory). A request to materialize a compressed section on a read/write descriptor fails with ELF_E_UNIMPL. Existing write behavior of noncompressed sections is retained. No compressor, writer, new symbol resolver or SHN_XINDEX reinterpretation is requested. Existing gelf_getsymshndx conventions remain unchanged: caller supplies the associated companion data.

elf_getdata performs the normal SHT-to-Elf_Type conversion after decompression. The file record count is derived from ch_size, not sh_size. Output d_type and native record sizing keep existing library rules, d_align=ch_addralign, d_off=0, d_version unchanged. Reject logical byte lengths that are not whole records for the existing type. For SHT_STRTAB, elf_strptr bounds and offsets refer to logical contents in both ordinary and ELF_F_LAYOUT handling. Do not bypass existing type checks or alignment-hole semantics for ordinary uncompressed data.

elf_rawdata continues to expose a stable ELF_T_BYTE descriptor over the actual physical section, with original d_size and alignment. elf_rawfile and all sh_* values are unchanged. Raw and logical descriptors and buffers are distinct; repeated reads of either return their own cached descriptor, normal descriptor iteration ends at NULL, and neither access order changes the other's bytes. Logical allocations are owned by the normal section/Elf lifetime; no singleton decompression scratch buffer. Failed materialization publishes no partial translated descriptor. A second failed attempt remains an error, raw reads and unrelated valid sections still work. No support for concurrent mutation or rewriting caller-owned elf_memory bytes is required.

Unknown compression type / compressed read-write view -> ELF_E_UNIMPL. Unsupported flags, invalid header/alignment, corrupt or mis-sized stream, and invalid logical record multiple -> ELF_E_DATA. Unrepresentable host size / arithmetic -> ELF_E_RANGE; allocation failure -> ELF_E_RESOURCE. elf_strptr at or above the logical bound -> ELF_E_ARGUMENT. Report through existing elf_errno/elf_errmsg; no new error API.

Implementation files may be added under libelf/*.c and are compiled automatically. Generated upstream converters are supplied with matching source-generator hashes. If changing their m4 inputs, regenerate using task_support/regenerate.sh and commit matching generated C/header; normal builds need no m4 and no Python. Keep zlib source and LICENSE unchanged.

Base fixture: an ELF64 LE ET_REL with sections 0=null, 1=96-byte .text, 2=SYMTAB, 3=STRTAB, 4=SYMTAB_SHNDX, 5=RELA targeting section 1. Symbol 1 is global function target at section offset 0x40, size 8, with st_name=192, raw st_shndx=SHN_XINDEX and companion value 1. Relocation 0 has r_offset=8, symbol=1, type=2, addend=-4. The string table is 256 bytes with target at 192. The compressed variant independently wraps sections 2..5 with standard ELF64 compression headers and zlib streams; all original relationships are identical. The source and delivered binary fixture SHA values are recorded privately by the author. Fixture construction contains no decompression/target implementation.
