CrawlHTTP API

Add HTTPOptions with MaxWorkers int, MaxPerOrigin int, MinOriginInterval time.Duration and Client *http.Client. Add CrawlHTTP(seeds []string, options HTTPOptions, follow FollowLink) ([]*Page, error). Positive worker limits and a nonnegative interval are required. Nil Client uses a private client; otherwise retain its Transport and Timeout without mutating the caller's client. HTTPOptions are immutable during a call. No cookies, robots fetching, retries or persistent cache are added.

URLs are absolute http/https, fragments stripped. Compare origins by lowercase scheme/hostname and effective port; preserve path and query identity. Validate configuration and every seed before making requests. Empty seeds return an empty result. Seeds bypass follow; an ordinary discovered link must pass follow. Nil follow permits discovered links. Redirect destinations do not go through follow: the request is completing an accepted page. Return one Page for every distinct accepted seed/discovered URL, not for redirect-only intermediates. Page.URL remains that logical URL. Ordering of Pages is unspecified.

Every physical GET occupies one global and one destination-origin slot until its response body has been consumed or closed, including redirects and unsuccessful responses. Do not let net/http automatically follow redirects. The next start at an origin must be at least MinOriginInterval after the most recent response at that origin finishes; active requests already started remain active. A positive interval therefore does not force serialization when MaxPerOrigin is greater than one. Before any response finishes, initial slots can start concurrently. A blocked origin cannot hold global worker slots or prevent an eligible origin's work from starting. Scheduling need not impose a fixed ordering among eligible origins.

301, 302, 303, 307 and 308 with Location continue as GET after resolving against that hop's URL. Close the response before releasing its slot and arranging the destination. Missing/invalid Location, unsupported schemes, redirect cycles, non-200 terminal statuses, transport and body-read failures terminate affected logical pages with FetcherError; independent pages continue. Successful terminal HTML is parsed once, relative links resolve against the final response URL, and its existing Links/Assets extraction semantics otherwise remain. Do not expose links from a failed body read. Redirect hops are not counted as HTML discovery depth, and no depth option is added.

Each normalized physical URL is fetched at most once per call. If a destination is queued, running or complete, attach to that work instead of sending again. Every waiting logical entry gets the same terminal content/error under its own Page.URL. Sharing a target is valid convergence, not a cycle. A cycle in redirect dependencies must finish all affected predecessors with errors. Cache results only within this call. Expand each successful terminal document's outgoing links once; sharing must not multiply discovery. Failed physical targets are shared errors, not retried. All response bodies owned by the crawler close exactly once. Return only after queued, active, delayed and redirect-dependent work has settled. Repeated calls do not share state.

Keep Crawl, Fetcher and NewHTTPFetcher source compatible, and retain custom body-only Fetcher support and existing old tests. Use the existing production fetch/parse pipeline for the old and new entry points rather than maintaining a separate HTML crawler in task_support. Update the sitemap example with -per-origin and -origin-gap flags to use the new scheduling, retaining -j and its JSON page output. New code, examples and tests are Go only.

Add http_schedule_target_test.go in package grawler_test with TestHopGates, TestHopSharing and TestHopCompletion. Each group wraps its actual checks with taskcheck.Run(t, func(c *taskcheck.C) {...}) and c.Check from github.com/frobware/grawler/task_support/taskcheck. Exercise real local HTTP servers with channel barriers; no external websites. Cover the limits, post-response interval with an independently progressing origin, final-base links and a queued/in-flight/shared target, cyclic dependencies and failed body reads, plus a second independent run. Keep time bounds wide and use barriers for ordering. The target runner compiles current production sources, runs these groups under the race detector and then the normal production baseline.
