# Tracked-origin reset

Add public methods to package agouti:
```
func (p *Page) EnableOriginReset() error
func (p *Page) OriginResetPending() []string
```
Existing `Page.Reset() error` performs tracked cleanup only after successful enablement; otherwise preserve the original requests and behavior. Put new production implementation in `origin_reset.go`, with necessary changes to the existing Page/API transport path. Keep `Page.Session() *api.Session` and the `api.Bus` Send interface compatible. No dependencies beyond Go's standard library.

Scope: one top-level browsing context per Page/session, initially at root. No concurrent manual window/frame switching, JavaScript-initiated navigation outside the listed commands, or multiple independent Page wrappers for the same remote session. HTTP WebDriver JSON Wire remains the protocol. No CDP/BiDi or actual browser is required.

Enable observes GET url and records its origin, then enables tracking. If observation fails it must not partially enable; repeated successful calls preserve pending progress. Canonical origins include lowercase http/https scheme and hostname, nondefault port and correct IPv6 brackets. Remove default :80/:443, ignore userinfo/path/query/fragment. Ignore valid non-http(s) URLs such as about:blank; malformed URLs are errors. Return an independent pending slice, in first-observed order, deduplicated by canonical origin.

After enabling, intercept these real production operations: Session.SetURL (POST url), Forward/Back/Refresh, api.Element.Click/Submit. This includes Page/Selection wrappers, elements retrieved before enabling, elements retrieved by GetElements/GetActiveElement and their descendants, and the direct Session methods. The public raw Send equivalent of these endpoints behaves the same. Do not require callers to adopt new navigation or selection types. Default sessions must not acquire extra URL probes.

For each listed attempted operation, sample GET url before sending it, then send the original operation exactly once, then sample GET url again even if the original operation was rejected. Record successful observations in order, including the actual final destination after a redirect and the departure origin. A failed pre-observation returns an error without sending the operation. A failed operation/post-observation never triggers replay. Preserve both reasons when both fail. A post-observation failure reports that the operation was attempted and leaves an observation gap; before Reset cleans anything, it must successfully sample the current URL to close that gap and add that origin. Assume the reported final document remains stable until the next listed command; do not invent intermediate redirect origins. An earlier command error alone need not disable the tracker. Observations should not depend on an assumed target URL or inspect form values.

Reset uses the pending ordered set. Visit `origin + "/"` for each item using existing navigation transport; obtain GET url and verify it still has the expected canonical origin before deleting anything. Redirect elsewhere is an error; do not clear the unexpected destination or add it to pending as a business visit. For the expected origin, clear cookies, local_storage and session_storage in that order. Retain the original Reset compatibility fallback for each storage endpoint: on its error, call Execute with `localStorage.clear();` / `sessionStorage.clear();`. A successful fallback counts as cleared; if it fails, return both reasons. Cookies have no script fallback. ConfirmPopup's ignored-error behavior may remain.

Only when all three clears for an origin succeed, remove that origin from pending. Stop at the first failed origin and retain it and the later ones; a later Reset retries that origin from cookie deletion, without revisiting previously completed items. A failed final navigation to about:blank returns an error with an empty pending list; another Reset only retries that navigation. Successful Reset leaves pending empty and goes to about:blank, while tracking stays enabled. Subsequent business navigation to a previously cleaned origin makes it pending again. Cleanup navigation and probes must not enroll origins or re-enroll completed items, including across a failed Reset. Never claim rollback of cookies or storage.

Each navigation's pre-observation, command and post-observation is one session operation boundary. The whole tracked Reset shares that boundary with all commands through the same Session, including old Element references. While cleanup is paused at the HTTP peer, a concurrent ordinary Navigate or direct Session.SetURL must not send its own request until cleanup returns; it may then start a new business visit. Separate sessions are independent. Do not hold a global lock and do not recurse through the tracking boundary when issuing probes/cleanup. Concurrent initialization itself need not be supported; enable before concurrent use.

Errors should identify the origin and stage when applicable. Returned pending slices must not permit callers to mutate internal progress. Document that visiting an origin root may execute page code and may fail/redirect; only already observed origins are cleanup targets. No external service or account is used by examples.

Add task_support/origin_reset_target_test.go (external package agouti_test), with TestOriginObservation, TestOriginCleanup and TestOriginCleanupRecovery using task_support/taskcheck.Run/c.Check in actual assertions. Build the real Page/Selection/Session/Element over a local HTTP state peer. Include default Reset and enabled behavior, canonical duplicates and actual redirect destinations, old and nested elements, direct Session calls, command failure with a changed document, URL observation errors, script fallback, cleanup redirect, partial progress and retry, final blank failure, pending-slice isolation and a channel-controlled concurrent navigation. Use channel handshakes, not sleeps. The provided baseline only exercises the default behavior; it does not implement this tracker. Add a Go README example of enabling, a multi-origin form flow, Reset and pending progress after an error.
