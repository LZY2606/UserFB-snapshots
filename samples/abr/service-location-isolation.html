Isolating throughput estimates by service location

By default dash.js mixes the throughput and latency measurements of all CDNs in a single sample window. When switching between a fast and a slow CDN this means that the history of one CDN influences the bitrate selection on the other.

Setting streaming.abr.throughput.isolateByServiceLocation to true keeps throughput, latency and EWMA measurements per media type and per service location. The service location of the last accepted MediaSegment measurement defines the active scope. The full history of a location is restored when switching back to it.

Use player.getCurrentServiceLocation('video') to query the active scope. It returns null when no media measurement has been accepted yet and the empty string for the unnamed location.
