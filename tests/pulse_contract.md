# 代数码本脉冲契约测试说明

新增测试 `tests/pulse_contract.c`（入口实现在 `support/target_main.c`，断言宏
`unit_check` 在 `support/check.h` 声明）。生产算法与公开 API 均未改动行为；
唯一的生产源码改动是 `amrwbenc/src/c4t64fx.c` 中一个仅在定义 `PULSE_TRACE`
时编译的只读观察点。普通构建不带该宏，没有回调、没有额外分配，输出码流
逐字节不变（已验证普通构建产物中不存在 `pulse_trace` 符号）。

三组测试：

| 组 | 驱动方式 | 比较对象 |
|----|----------|----------|
| `test_inverse` | 直接调用 `ACELP_4t64_fx()`，输入为冻结的合法相关向量/冲激响应 | 索引独立反解出的 64 采样 vs 观察点记录的原始 `code[]` |
| `test_serial` | VisualOn DEFAULT 参数流（16 位 BIT_0/BIT_1 字） | 逐位读出的码本索引 vs 观察记录，再反解逐采样比较 |
| `test_stream` | 公开 `E_IF_encode()`（RFC 3267 MIME 字节流） | 经排序逆置换还原参数位后，同 `test_serial` 比较 |

---

## 1. 独立逆索引的依据

逆索引完全按 `amrwbenc/src/q_pulse.c` 三个量化函数的位格式重新实现，
测试本身不调用任何 `quant_*` 函数，也不从 `code[]` 反抄期望值——期望值
只来自观察点记录的原始激励，方向上是“索引 → 激励”的独立证明。

四轨码本每轨 16 个位置（0..15），四个轨按 `采样号 = 4*位置 + 轨号` 交织
成 64 个采样；脉冲幅度为单位幅度（观察记录中的 `pulse_amp`，本编码器为
Q9 的 512），符号为 ±1。

### 1.1 单脉冲 `quant_1p_N1`，N=4，共 5 位（20 bit 模式）

低 4 位是位置，最高位（bit4）是符号位，1 表示负脉冲：

```
pos = idx & 0x0F ; sign = (idx & 0x10) ? -1 : +1
```

### 1.2 两脉冲 `quant_2p_2N1`，N=4，共 9 位（36 bit 模式、44 bit 后两轨）

9 位 = 两个 4 位位置字段 `hi`、`lo` + 1 个最高位。**最高位不是两个独立
符号位**。两个位置字段按大小关系存放，位置的大小关系同时承载符号关系：

- `hi <= lo`：两脉冲同号，最高位给出共同符号；`hi == lo` 即同一位置两个
  同号脉冲，反解为重数 2，重建时在该采样累加两个单位幅度，而不是当成
  集合去重。
- `hi > lo`：两脉冲异号，最高位给出 `hi` 脉冲的符号，`lo` 脉冲取反号。

这正是“异号位置先后相反”情形的编码方式，测试用冻结向量和固定种子
属性测试同时覆盖了 `hi>lo` 且最高位为 0/1 两种分支。

### 1.3 三脉冲 `quant_3p_3N1`，N=4，共 13 位（52 bit 模式、44 bit 前两轨）

13 位从高到低：

```
[ 5 位单脉冲 ][ 1 位半区标志 ][ 7 位脉冲对 ]
```

- 5 位单脉冲就是一个 N=4 的单脉冲码（4 位位置 + 1 位符号）；
- 7 位脉冲对是 N=3 的两脉冲码（位置范围 0..7）；
- 单脉冲位置自身的 bit3 与单独的脉冲对半区标志分别决定两组落在哪半个
  8 位置区间，二者可以不同——这就是三脉冲分解的两个半区不对称情形，
  冻结向量对 `半区标志=0/1` 两条递归分支都安排了不对称位置。

### 1.4 各模式的轨布局（不可按四条等长轨处理）

| 模式 | 每轨脉冲数 | 每轨索引位宽 | 合计 |
|------|-----------|--------------|------|
| 20 bit | 1,1,1,1 | 5,5,5,5 | 20 |
| 36 bit | 2,2,2,2 | 9,9,9,9 | 36 |
| 44 bit | **3,3,2,2** | **13,13,9,9** | 44 |
| 52 bit | 3,3,3,3 | 13,13,13,13 | 52 |

重建时对每个解码脉冲执行 `exc[4*pos + track] += sign * pulse_amp`，
同位置同号脉冲自然累加；最后把 64 个采样与观察到的原始 `code[]`
逐采样比较。

## 2. 观察点的位置

- 回调类型与记录结构定义在新增内部头 `tests/pulse_trace.h`：
  `pulse_obs_t` 记录每个子帧的 `nbbits`、单位脉冲幅度 `pulse_amp`、
  四个轨的原始索引 `index[4]` 和 64 个采样的原始激励 `code[64]`，
  全局回调指针 `pulse_trace_cb` 默认为空。
- 观察点位于 `amrwbenc/src/c4t64fx.c` 的 `ACELP_4t64_fx()` 末尾，
  在所有模式的索引构建 `if/else` 链（`quant_1p/2p/3p...`）完成、
  `code[]` 与 `_index[]` 都已定型之后，函数 `return` 之前；对应到
  `amrwbenc/src/voAMRWBEnc.c` 的调用处，就是 `ACELP_4t64_fx()` 返回后、
  coder 对 `code[]` 做 `Preemph()` 预加重和 `Pit_shrp()` 音高增强
  （约 1159-1161 行）之前。因此记录到的是未经后续处理的原始码本激励。
- 整段代码包在 `#ifdef PULSE_TRACE ... #endif` 内，只做结构体赋值和
  只读回调，不修改任何生产变量；宏关闭时回调指针与分支都不存在，
  也没有额外内存分配，正常构建码流不变。

## 3. 参数流的布局

### 3.1 DEFAULT 参数流（`test_serial`）

`PackBits()` 在 `bitstreamformat == 0` 时输出：3 个 16 位字
（同步字 `0x6b21`、帧类型 `TX_SPEECH`、模式号），随后是
`nb_of_bits[mode]` 个 16 位字，每个字取值 `BIT_0(-127)` 或 `BIT_1(127)`。
测试先逐字校验确为 BIT 标记，再翻译成 0/1 规范比特序列，绝不扫字节
碰运气找相同索引。

`coder()` 中 `Parm_serial()` 的实际布局（MSB 先传）：

- 帧头 47 位：1 位 VAD + 46 位 ISF（高于 7k 模式的 46 位 ISF 量化器）；
- 每个子帧依次为：音高基频 → （仅高于 8.85k 模式）1 位 `select`
  → 四个码本轨索引 → 固定码本增益。

| 部件 | 8.85k(模式1) | 其余四个被测模式(2..4) |
|------|--------------|------------------------|
| 子帧 0/2 音高 | 8 位 | 9 位 |
| 子帧 1/3 音高 | 5 位 | 6 位 |
| select | 无 | 1 位 |
| 码本索引 | 见 1.4 位宽表 | 同左 |
| 增益 | 6 位 | 7 位 |

逐位读取器 `SerialReader` 按上述顺序推进，码本字段严格按
1.4 的每轨位宽连续读取；读完四个子帧后断言读取位置恰好等于该模式的
串行长度 `nb_of_bits`（177/253/285/317），任何布局假设错误都会立即暴露。

### 3.2 RFC 3267 MIME 流（`test_stream`）

`E_IF_encode()` 默认 `VOAMRWB_RFC3267`：1 个 ToC 字节
（`toc_byte[mode]`）+ `packed_size[mode]` 个压缩字节。`PackBits()` 按
`mime_io.tab` 的 `sort_ptr[mode]` 置换表把规范参数位重新排序后，每字节
MSB 优先打包。测试对序列位置 `k` 用 `sort_ptr[mode][k]` 做**逆置换**
还原出规范串行位，再复用 3.1 的同一套布局计算和读取器，因此不是靠
字节扫描匹配索引。

两组流测试都用内容不同的连续确定性 PCM 帧在模式 1..4 间轮换，把观察到
的每个子帧（每帧 4 个）独立反解并逐采样比较；生成数与比较数都按实际
发生计数（索引比较数 = 帧数×4×4，采样比较数 = 帧数×4×64），而不是只
统计模式名是否出现过。

## 4. 两种变异分别由哪组的哪些实际数据发现

`support/target.sh` 会在临时源码树中分别打两个补丁，用**完全相同的输入
内容**重跑测试，要求以 `ASSERT` 行和退出码 42 报告差异；编译失败或崩溃
都不算发现。两次都在 `test_inverse` 组的冻结向量子帧上被捕获。

### 4.1 `sign2.patch`：丢弃两脉冲索引的符号位

补丁把 `quant_2p_2N1()` 的返回值改成 `index & 255`，清掉 bit8。

- 捕获组：`test_inverse`，断言标签
  `inverse: frozen index rebuilds raw excitation`。
- 实际数据：冻结向量的 **36 bit 子帧**。正常四轨索引为
  `375, 472, 240, 192`，变异后变成 `119, 216, 240, 192`
  （375 & 255 = 119，472 & 255 = 216；符号位被抹掉）。
- 独立反解与观察到的原始激励在 3 个采样上不符：
  采样 28：反解 +1024 vs 实际 −1024；采样 33：−512 vs +512；
  采样 53：+512 vs −512。
- 20/44/52 bit 子帧不报：20 bit 走单脉冲码，44/52 bit 的两脉冲轨
  （索引 240、192）bit8 本就为 0，`&255` 是恒等变换。这恰好证明测试
  针对的是两脉冲符号语义，而不是偶然失配。

### 4.2 `track44.patch`：交换 44 bit 模式最后两轨的索引

补丁把 44 bit 分支中后两轨的 `_index[track]` 改成 `_index[track ^ 1]`。

- 捕获组：`test_inverse`，同一断言标签。
- 实际数据：冻结向量的 **44 bit 子帧**。正常索引为
  `6015, 4584, 240, 192`，变异后第 2、3 轨被互换为
  `6015, 4584, 192, 240`。
- 轨 2、轨 3 的脉冲被放到对方轨上，独立反解与原始激励在 4 个采样上
  不符：采样 50（反解 512 vs 实际 0）、51（0 vs 512）、62（0 vs 512）、
  63（512 vs 0）。
- 36 bit 子帧虽也调用 `quant_2p_2N1()`，但补丁只在 `nbbits == 44`
  分支内，故不受影响——差异被精确定位到 44 bit 的 3,3,2,2 非等长轨
  布局处理上。

## 5. 运行方式

- `bash support/baseline.sh`：12 帧确定性 PCM 冒烟测试，校验帧类型与
  长度，输出 `AMRWB_BASE ...`。
- `bash support/target.sh`：编译并运行三组测试（输出
  `AMRWB_PULSE_OK`），再分别对 `sign2`、`track44` 两个变异源码树要求
  以 ASSERT + 退出码 42 失败，最后联跑 baseline 回归。
