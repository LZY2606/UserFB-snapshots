# MSF 7.00 结构化 fuzz 回归说明

这一页说明 `tests/msf_model.rs` 与 `tools/check-msf-mutants.mjs` 的设计边界：样本从哪里
生成、期望值从哪里来、以及明确**不**覆盖哪些格式范围。所有样本都由 Rust 在内存中合成，
不下载任何 PDB，不访问符号服务器，也不执行文件里的任何字节。

## 测试入口

四个顶层测试，名字固定，由 `baseline/run-target.sh` 校验确实执行：

| 测试 | 验证内容 |
| --- | --- |
| `model_layout` | 模型自洽性、三种流（不存在 / 零长度 / 有内容）、跨页流、跨页目录、手工反例 |
| `relocation_law` | 同一逻辑模型在不同物理排布下，`PDB::open` 与 `raw_stream` 结果逐字节相同 |
| `lazy_errors` | 受限损坏下只能报错，不能拼出伪内容；单流损坏不连累合法兄弟流 |
| `source_views` | 记录型 `Source` 上的片段拼接顺序、尾片段长度、已返回视图的存活 |

## 生成域（generation domain）

- **页大小**：固定覆盖两种，`512` 与 `1024` 字节（MSF 7.00 头允许的 2 的幂区间
  `0x100..=128*0x10000` 之内）。
- **物理布局**：每种页大小都生成三种排布——正向连续页（forward）、逆序页（reverse）、
  高低地址交替的间隔页（interleaved）。排布不仅改变单次分配内部的页序，还会整体搬移
  页号表（locator）、目录、载荷三类页面所在的物理区域，所有引用随之更新。
- **逻辑流种类**：每个模型混合三类流——`Absent`（目录里记为 `0xffffffff`，不占页号）、
  `Empty`（长度为零、存在但无页号）、`Data`（真实字节）。
- **流长度**：生成的有内容流都跨越至少一个页边界，且最后一页只使用一部分；
  因此“末页按流长截断”是被真正压到的路径，而不是整页特例。
- **目录规模**：通过流数量与流页数控制，目录在两种页大小下都真实地占据 **≥2 页**。
- **样本上限**：任何单个镜像不超过 `1 MiB`（`MAX_SAMPLE`），并断言满足库读取 4096 字节
  头部视图的最小长度要求。
- **确定性**：载荷由固定种子（`RNG_SEED`）的 xorshift 生成器产生，跨机器可复现；
  另含一个完全手工指定页号、带物理空洞与逆序两页流的小型反例（`hand_model`）。
- **页尾填充**：所有未被拥有的字节填 `TAIL_FILL = 0xA5`，且生成的载荷字节保证不等于
  该值。这样一旦末页没有按流长截断，就会泄露出可逐字节区分的填充值，流末尾无法“借”到
  这些字节。

## 独立期望的来源（independent expectations）

- 模型自己保存逻辑流列表与每条流的原始字节（`Logical` / `Model`），由这些字节独立地
  构造目录字节流（流数量、每个流的长度、再按序排列的载荷页号），再写入镜像。
- 期望值**从不**经生产解析器读回目录来计算。断言比较的是 `raw_stream` 返回的字节与模型
  持有的原始字节、模型记录的物理页号，以及模型独立预测的 `SourceSlice`。
- 对 `Source` 片段的期望由测试内独立实现的 `predict_slices` 给出：它复述“连续页合并、
  最后按长度截断”两条规则，而不是调用生产代码里的 `PageList`。
- 损坏测试的期望是显式的错误类别（`PageReferenceOutOfRange`、`IoError` 等），并且额外
  断言不会出现成功返回的拼接内容；只检查“返回长度”或“没有 panic”不算通过。
- 记录型内存源 `RecordingSource` 自身遵守 `Source` 约定：请求越界时返回真实
  `io::Error`，绝不返回长度不符的视图。因此观测到的错误来自文件 / I/O，而不是测试源
  违反约定触发的 assert。

## 受限损坏范围（corruption scope）

损坏只在说得清的类别内探索：

1. 把某条流的载荷页号改成 `0`；
2. 把某条流的载荷页号改成超过头部 `pages_used` 的值；
3. 截断目录、页号表，或截断某条流末页的真实载荷字节。

库可以在 `PDB::open` 时返回既有错误，也可以在惰性读取时返回，但任何情况下都不能成功
返回一份拼出来的伪内容。若只破坏一条流的载荷引用而目录完整，访问该流失败后，合法的
兄弟流仍必须能读出与模型一致的字节。

## 退化（mutation）校验

`tools/check-msf-mutants.mjs` 先在临时副本里确认原始版本通过，再在各自独立的临时源码
副本中注入三种库层退化，验证新断言能抓住它们：

- 不存在的前置流错误地占用页号位置；
- 非连续页被错误地合并成连续读取；
- 最后一页不按流长截断。

每个副本都必须仍能编译；只有当测试实际执行、且失败指向针对真实字节、请求片段或错误
结果的断言（测试内嵌的 `msf-*` 标记）时才算抓住。编译失败、缺测试、零用例、超时都不算。
脚本会输出退化名以及最小失败样本的模型、页布局与实际差异，并在结束后校验原 `src/`
树哈希不变。

## 明确排除的格式范围

- 只覆盖 **MSF 7.00（BigMSF）**。库尚未实现的 small MSF（2.00，`JG` 魔数）不在范围内。
- 不覆盖 MSF 之上的任何高层流语义：TPI/IPI、DBI、模块信息、符号记录、OMAP、字符串表等
  均不构造、不解析。回归停在“目录决定字节从哪里来”这一层。
- 不做魔数损坏、非法页大小之类的头部模糊；头部始终保持合法，损坏仅限上面列出的类别。
- 不使用 `fixtures/` 下的下载型 PDB，不访问网络或符号服务器，不依赖外部 fixture。
- 不执行镜像中的任何内容；样本是纯数据，载荷字节只是确定性的无意义填充。
- 不修改既有依赖、`Cargo.lock` 或旧测试断言；生产库行为保持不变。
