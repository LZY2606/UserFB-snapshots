# Label 调试名称

当 `ReadBinaryOptions::read_debug_names` 为真时，WABT 会读取标准 `name`
自定义节中的 `label` 子节（子节 id 为 `3`）。该子节是按函数分组的间接名称表：

```text
label_names ::= vec(label_names_per_func)
label_names_per_func ::= func_index label_name_map
label_name_map ::= vec(label_name)
label_name ::= label_index name
```

## 函数索引与标签编号

- `func_index` 包含导入函数前缀。例如索引 `0` 是导入函数时，第一个本地定义
  函数的索引是 `1`。
- 导入函数不能拥有非空标签名称表。
- 标签索引在每个函数内独立，从 `0` 开始。
- 标签索引按照 `block`、`loop`、`if` 的开操作码在二进制中出现的顺序编号。
- 函数隐式出口、`else` 和 `end` 不占标签编号。
- `if` 两臂中的内层节点进入同一个开序序列：先给 `if` 本身编号，然后是 then
  臂中的节点，再是 else 臂中的节点。

这里的标签索引不同于分支立即数中的相对深度。深度取决于分支位置处的控制栈；
标签索引则是整个函数内稳定的节点标识。`ApplyNames` 继续使用已有的词法标签栈，
把数值深度转换为对应节点的唯一文本名。深度等于当前打开的结构标签数量时表示
函数隐式出口；该分支保持数值形式，不会被改写成内部标签。

当前编号覆盖 `block`、`loop`、`if`；其他指令仍由原有 binary reader 正常消费。

## Name 节位置

`name` 节既可以放在函数节之后、code 节之前，也可以放在 code 节之后。
`ReadBinaryIr` 会复制名称字符串，并在所有节读取完成后把名称绑定到 IR 标签
节点，因此调用者不需要再次手动绑定；`ReadBinaryIr` 返回后即可释放输入字节。

## 名称转换与冲突

调试名称沿用 WABT 既有习惯：

- 空 UTF-8 名称表示没有提供名称。
- 非空名称会加上既有的 `$` 前缀。
- `WriteWat` 在需要时沿用既有 WAT 标识符合法字符转换规则。
- 名称按函数独立处理并消除歧义。

如果多个标签节点提供相同名称，则按开序处理：第一项保留转换后的调试名，后续
重名项选择最小可用的 `.1`、`.2` 等后缀。选择后缀时，调试表后面显式给出的名称
也视为已占用。

调用 `GenerateNames` 生成自动名称前，会先收集函数内所有已有标签名，包括开序
靠后的节点上的调试名，因此自动名称不会与任何调试名碰撞。自动名称自身需要
消歧时沿用名称生成器既有后缀形式，例如 `$B0_1`。

不调用 `GenerateNames` 时，未命名标签仍为空。`ApplyNames` 只会替换目标具有
非空唯一名称的分支变量；指向未命名标签或函数出口的分支继续保留数值深度，
`WriteWat` 仍可输出这些深度。

## 错误与关闭调试名称

当 `ReadBinaryOptions::fail_on_custom_section_error` 为真时，重复或逆序的
函数组/标签索引、截断名称、越界函数或标签索引都会以二进制位置报告错误。
之后的独立读取使用全新的 reader 状态，不会受上一次失败影响。

`read_debug_names=false` 时仍按原行为忽略这些调试名称；普通无名称模块以及
已有的函数名、局部变量名读取保持可用。
